# Ledger Management System

A management system built around the "member tasks + purchase flow + multi-level commission" scenario.

The **member side** is a mobile H5 app (Vue 2 + vue-router, hash routing, laid out on a 750rpx phone grid), and the **admin backend** is server-rendered with Laravel Blade. Both share a single Laravel application and a single database. SQLite is the default, so a fresh clone runs after two commands.

---

## Features

### Member Side (H5)

| Module | Description |
| --- | --- |
| Login | Username / password sign-in, plus the registration entry |
| Home | Shop info, banner carousel, navigation grid, notice bar, today's task |
| Purchase List | Tabbed by status (pending payment / pending confirmation / confirmed / completed); only tasks assigned to you are shown |
| Order Detail | Buyer and seller info, task amount, payment QR codes listed by serial number (No. 1 is the preferred default), upload payment proof |
| Team Purchases | Order and earnings statistics for direct and indirect downline |
| Mine | Order earnings, direct-referral earnings, withdrawable balance; edit avatar and nickname, shipping addresses, change password, log out |
| Statements | Earnings detail, balance detail, withdrawal records, with paged loading |

### Admin Backend

| Module | Description |
| --- | --- |
| Dashboard | Member count, task count, money flow, pending items |
| User Data | Every field searchable and editable; create users, enable / disable, delete, adjust balance, bulk purge |
| Purchase List | Publish a task: pick the seller (with smart recommendation) → enter the task amount → pick the buyer |
| Purchase Records | Review payment proof uploaded by users, manually confirm or cancel arrival (tiered rewards are issued automatically) |
| Fund Details | All transactions, filterable by member, type and date |
| Withdrawal Review | Approve or reject withdrawal requests |
| System Settings | Shop name, banners, navigation grid, notices, task return rate, self-registration toggle |
| Operation Logs | Audit trail for every backend action |
| Admin Accounts | Up to 5; split into super admins and normal admins |

**Permission tiers**: a normal admin can only arrange tasks for users (Purchase List / Purchase Records); user data, funds, withdrawals, settings and logs are visible to super admins only.

---

## Core Business Rules

Task repayment = principal + own earnings, where own earnings = principal × return rate.

- **Configurable return rate**: 1.5% by default globally (adjustable in the backend, 1%–100%); a dedicated rate can also be set for an individual member;
- **Direct-referral reward**: when a downline member takes part in a task, that member's direct referrer receives 0.5% (credited to balance);
- **Shop owner earnings**: the owning shop manager receives 1.5%;
- **Platform retention**: 0.5%.

> Accounting scope: a member's "order earnings" only accumulates the earnings generated by that member's own task participation (principal excluded); "balance" only accumulates rewards generated by direct downline participation, and that is the part which can be withdrawn.

## Tech Stack

| Layer | Choice |
| --- | --- |
| Backend | PHP 8.1+ / Laravel 10 |
| Database | SQLite (default, works out of the box) / switchable to MySQL |

## Quick Start

```bash
# 1. Install dependencies
composer install

# 2. Prepare environment variables
cp .env.example .env
php artisan key:generate

# 3. Initialize the database (tables + admin account and site settings, no business data)
touch database/database.sqlite
php artisan migrate --seed

# 4. Run
php artisan serve --port=9193
```

Open <http://localhost:9193/> to reach the member side.

To generate a batch of demo data (members / tasks / earnings):

```bash
php artisan db:seed --class=DemoSeeder
```

> Before going live, be sure to change the password under "Account Settings", and to replace `APP_KEY` and `JWT_SECRET` in `.env`.

## Directory Structure

```
app/
  Http/Controllers/Admin/   Admin controllers (users, tasks, records, funds, withdrawals, settings…)
  Http/Controllers/Api/     Member-side APIs (login, home, member, file upload)
  Http/Middleware/          AdminAuth / SuperAdmin / ApiAuth
  Models/                   Member, Order, Balance, Cash, Cert, Address, Setting, Admin
  Services/FlowService.php  Task settlement and commission logic
config/flow.php             Business parameters (service fee, tier ratios, statement types)
database/migrations/        Table schemas
database/seeders/           Seed data and demo data
public/static/              Member-side frontend assets (JS / CSS / images / fonts)
resources/views/admin/      Backend page templates
routes/admin.php            Backend routes
routes/api.php              Member-side API routes
```

## Notes

- The member frontend needs no build tooling: edit `public/static/js/*.js` and refresh the page;
- Every create, update and delete in the backend is written to `admin_logs` and can be traced under "Operation Logs";
- Image uploads go through `/app/File/upload` and are stored in `public/uploads/<year-month>/`, limited to 8 MB, supporting png / jpg / gif / webp.
